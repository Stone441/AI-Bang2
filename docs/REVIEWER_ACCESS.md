## 账号、权限与审计的边界

登录表单只接受账号和密码，后端根据私密账号表映射到已接入的源身份；客户端 role/user_id、问题文本和模型输出均不能赋权。密码以独立盐的 scrypt 哈希保存，账号卡片另存本机用于交付。错误密码和不存在账号使用相同失败提示，并有登录失败限速。

会话一小时到期，账号本身有到期时间及 active 开关。撤销账号或更换 revision 会使旧会话失效。账号间历史与引用预览隔离，访问已保存答案时仍检查当前源权限及版本。审计记录演示账号、有效源身份及相同 request_id，可关联原有源授权、模型和回答记录。

多人共用一个演示账号时，审计只能区分该账号，且共享这个账号的历史，不能识别实际坐在电脑前的人。如需逐人区分，可以给不同评委生成不同用户名，映射到相同演示角色。当前账号系统不是企业 SSO；评委账号不具备审计管理、源连接管理或预算修改能力。

当前真实环境使用服务端明确配置的团队源连接，不需要为三个应用演示角色重复配置四个平台。应用白名单在检索前、模型发送前、最终返回、历史和预览时生效；未知资源默认不放行，角色配置缺失也不会回退到全部原生权限。账号或策略在一次操作中改变时停止交付。

建议用工程账号问事故原因，用产品账号问 `Can we offer payment-retry to all customers today?`，再用外部协作方问同一发布问题，比较可用证据。产品和外部协作方不能看到未授权的事故根因原文、标题或命中信息。切换账号前先退出登录；同一账号在多人之间共享时，也共享该账号的历史。

真实员工逐人在源平台上的独立权限验证仍是不同的能力，不包含在此次获批演示范围里，不能用应用角色测试替代它。

## 线上评审的交付安排

预期体验：团队私下向评委提供 HTTPS 地址和演示账号密码；评委打开页面、登录、点击预设问题、查看引用和自己的账号历史。GitHub 用于源码复现，不能代替托管的应用。

本轮已准备精确 HTTPS Origin、Secure Cookie、同源/CSRF 检查和独立演示账号入口；后端仍只绑定 127.0.0.1。公网 TLS、DNS、防火墙、服务器运行维护及远程凭据存储尚未部署或验证。因此当前不能发送一个可用的公网演示 URL。

部署前还需确定：服务器/域名归属与费用上限、允许开放的账号和合成资料、活动结束后的关闭时间，并完成 G1 观看。现有 Mac Keychain 授权不能通过克隆 GitHub 自动搬到云服务器；云端需要团队单独安全配置凭据与 OAuth 刷新授权。不得上传本机数据库、Keychain、账号卡片或对话证据来“让克隆直接可用”。

具体配置草案见 [部署准备与发布步骤](REVIEWER_DEPLOYMENT.md)。不引入 ADP/TRTC、不更换模型后端。腾讯产品资格的群聊澄清与待确认一句话一并记录在该文档。
