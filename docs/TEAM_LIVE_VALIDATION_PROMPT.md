## 4. S-01：真实四源问答与新模型模式

先确认四个来源实际可读及当前提问者身份。选择获批合成资料，记录原始内容/版本及实际源ID。先制定固定小题集和语义标准，再跑结果，不能看完答案修改标准来凑通过。

建议首批6题：事故原因与撤回假设；已完成工单与仍在进行的工作；代码Done是否等于发布批准；试点/全面发布/未知发布日期；同一范围且尚未解决的矛盾记录；中文或多部分问法。若获批资料缺少对应情形，记录缺口，在获批合成范围内准备，不伪装为已有真实业务案例。

在模型费用和次数上限获批后，用相同身份/资料比较既有source-review模式和可选sectioned-synthesis模式，各题每模式先跑一次，保留全部失败。先检查实际入口是否支持--answer-style sectioned-synthesis，不凭印象拼接performance_trial等脚本参数；不要为测试切换共享服务。

分题模式有证据时通常需要生成、复审两次调用，不能把一题记成一次调用。检查简短结论、全部子问题、精确引文及原文预览、必要限定、错误前提纠正、未决冲突双方引用、未知与否定的区别。普通是非问句不自动算错误前提；较新修改日期或平台名不自动代表权威。失败草稿不得混入最终回答或历史。

机械检查与人工语义评审分列。只核对引用文字/关键词不能证明结论正确；参考答案不是唯一允许措辞。记录真实调用数、供应商usage/收据、预算占用、未知用量以及页面完整返回时间。

在获批Confluence、Jira、Slack、Drive合成范围内，每源验证新增、同一对象连续两轮修改。保持同一同步进程运行，观察后台发布后再验证答案/引用，不能用重启、全库重建或查询时恢复冒充后台已同步。

记录源端修改时间、本地观察/发布/索引时间、首次包含新内容的答案时间、实际版本和时钟误差。区分后台发现成功与查询时版本恢复成功；额外核对Jira/Slack内容指纹变化。按手册分钟级到约一小时的要求和事先约定窗口判断，不从单次本地耗时推断SLA。

通过有界状态读取观察同步，避免不断付费提问。验证来源不可用后的停止/过期显示和恢复；故障注入仅在隔离实例实施，不停用共享凭据。注入故障应标明，并非原生平台真的故障。超出窗口或版本不符就保存失败，不删样本。

## 7. S-04：在源端真实撤权并恢复

对明确获批的测试账号和合成对象，先成功读取并保存问题ID/引用/原权限快照，再在源平台撤权。在同一登录会话中检查新问题、旧History、旧引用均停止提供该对象，其他允许资料仍能使用。记录源端操作、传播延迟、模型前和最终返回检查的实际结果。

条件允许且额度已批准时，做一次受控的生成期间撤权；不要为卡时间反复付费重试。已经合法显示或已发送给模型的字节不能撤回，不把这一点写成系统已能收回。

测试结束按原权限快照恢复，仅恢复原授权，不扩大权限；记录恢复结果。禁止拿共享业务对象或真实员工权限做未经确认的实验。原生操作失败、未传播或恢复失败均保留并汇报。
