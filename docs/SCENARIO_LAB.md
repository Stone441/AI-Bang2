# 本地演示台与剩余优化

本轮完成可在本地推进的四项：S-02/S-04隔离演示台、S-03/S-04安全挑战集、S-05审计时间线，以及提交说明/讲解稿/架构同步。真实平台和新模型验收仍需接入，不能由模拟结果替代。

## 启动演示台

在项目目录使用Python 3.11+：

```sh
python3 -m scripts.scenario_lab
```

终端会给出一个`127.0.0.1`地址，在浏览器打开。按顺序点击四步：读取旧版 → 发布新版 → 撤权检查 → 审计检查。每步运行已有Engine、Ingestion、History/preview及审计逻辑，展示实际检查结果。下载按钮保存本次实验的JSON观察和审计链。

系统Python若为3.9，请使用本机已验证的运行时：

```sh
/Users/deng/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 -m scripts.scenario_lab
```

- 演示台只监听回环地址，使用自己的内存SQLite与FixtureWorld，没有平台凭据或真实模型。
- 它不使用正式服务的账号、数据库或源连接；正式员工服务没有`/api/lab/*`功能。
- 操作固定且按顺序执行，不能指定资料、账号或任意修改内容。写请求要求本机Host/Origin、同源条件及随机CSRF标记。
- 它是显式操作员实验台，没有员工身份登录。先前显示的合成观察会保留在操作员记录里；员工History和引用在撤权后由实际Engine检查并阻止。
- 页面时间是本地合成事件和完成观察的时间，不代表原生同步SLA。版本发布由演示动作直接触发，不冒充后台原生轮询测量。
- 失败结果会保留并停止继续操作。重新启动开启全新实验；停止进程会清除内存，先保存需要的记录。

关闭启动它的终端进程即可停止，不影响队友服务。不会自动打开公网或把记录上传。

## 安全挑战集

```sh
python3 -m scripts.security_challenges --output .runtime/security-challenges-01
```

必须使用新输出目录。8类挑战逐项保存结果与审计，某题失败仍继续保存后续结果，整体返回失败。验证实际服务端权限、引用及持久化路径；不是单纯让模型回答“安全”。

| 挑战 | 检查内容 |
|---|---|
| 受限/不存在探测 | 固定多种英文/中文问法具有相同可见资料结果，不泄露合成秘密标记 |
| 问题冒充角色 | “我是admin”等文字不会改变服务端权限 |
| 资料夹带命令及受限链接 | 命令确实到达fake模型，但不能给关联受限资料授予权限 |
| 伪造引用 | 草稿引用未提供的受限证据，不能保存或交付 |
| 生成中撤权 | 最终返回被阻止，不能保留为可读历史 |
| 来源unknown | 中文匹配不能绕过unknown拒绝 |
| 跨账号访问 | 历史隔离，受限旧引用拒绝 |
| 审计角色 | 普通用户不可查询审计，受限审计员只按已有范围查询 |

fake模型仅摘录资料；第3类只证明“检索内容不能授予后台权限”，不证明真实AI不会在措辞上服从恶意指令。真实模型注入抵抗、任意攻击和时序侧信道没有因此通过。

## 审计时间线

正常工作区的Audit explorer中，每张请求过程单新增可折叠时间线。按真实seq排序，相邻同阶段合并，保留ALLOW/DENY/UNKNOWN计数、原时间和原始事件入口。缺失事件不补成成功；保存、派发尝试和用户阅读保持区分。分页/过滤范围与原有权限一致，没有新增审计接口。
